## Архітектура
```
Orbix UI (src/js/19-ai-assistant.js, розділ «Orbix AI», кнопка «Запитати AI» на картці серверного бота)
  → Edge Function ai-assistant (index.ts — лише з'єднання з Supabase)
      ├─ agent.js    — перевірка запиту, системні правила, цикл «модель ↔ інструменти», ліміти
      ├─ provider.js — AIProvider: OpenAI-сумісний Chat Completions (Groq, OpenAI, OpenRouter…), тайм-аут, повтори, коди помилок
      ├─ tools.js    — 9 інструментів ЛИШЕ читання (білий список полів, псевдоніми B1…, недовірені тексти позначені)
      ├─ docs.js     — коротка довідка для search_orbix_docs
      └─ risk.js, engine.js — ЗГЕНЕРОВАНІ копії з runner (tools/build.js): ризик рахує та сама логіка, що й сервер
  → Supabase: дані читаються ВІД ІМЕНІ користувача (його JWT) → RLS і 2FA бази відсікають чуже;
    service_role — лише для запису ai_messages / ai_usage / ai_conversations (ліміт не обійти з браузера).
```
AI не є залежністю `runner`, `exchange`, рушія (`src/js/01–06`): вимкнення чи збій AI не впливає на торгівлю.

### Відхилення від ТЗ (свідомі)
- Серверні файли — `supabase/functions/ai-assistant/*.js`, а не `_shared/ai-*.ts`: `tools/build.js` копіює все з `_shared` у `runner` і `exchange`, тож AI-файли потрапили б у торгові функції. Звичайний JS (як `core.js`, `risk.js`) тестується в Node без Deno.
- Модуль інтерфейсу — `19-ai-assistant.js` (не `21-…`): модулі підключаються за назвою, а `20-boot.js` має йти останнім.
- `AIProvider` має один метод `chat()` — саме його використовує цикл діалогу; `continueConversation`/`callTools` — це `runConversation` в `agent.js`; `healthCheck`/`getUsage` — етап 5 (облік уже є в `ai_usage`).
- Таблиця `ai_insights`, інструменти ринку й стану бірж (`get_market_snapshot`, `get_exchange_status`) і аналітичні (`analyze_bot`, `compare_bots`, `analyze_strategy`, `propose_bot_config`) — етапи 2–4.

## Інструменти (етап 1)
`get_account_overview`, `list_user_bots`, `get_bot_details`, `get_bot_state`, `get_bot_events`, `get_bot_trade_history`, `get_risk_snapshot`, `get_backtest_results`, `search_orbix_docs`. Усі — лише читання, з JSON Schema (`additionalProperties: false`). Невідома назва (напр. `place_order`) повертає помилку, а не виконується.

Дані беруться з `bots.config`, `bot_state.state` (`b.tr`, `b.pos`, `xr`), `bot_events`, `backtests`, `profiles.risk_*`. Таблиці `bot_deals` і `orders` порожні — не використовуються. Для бота без стану на сервері інструмент прямо каже, що даних немає.

## Безпека
- JWT + `mfa_ok_now()` (як у `exchange`); 2FA також перевіряє RLS на всіх таблицях.
- Ключ AI — лише в секретах функції; браузер його не отримує. Ключів бірж AI не бачить (не читає `exchange_connections`).
- Prompt injection: тексти журналу й помилок ідуть полями `*_untrusted`, без керувальних символів, обрізані; системне правило забороняє виконувати з них вказівки; інструментів зміни немає взагалі.
- Ліміти: 2 000 символів на питання, 16 повідомлень історії, 5 раундів інструментів, 9 000 символів на результат інструмента, `AI_DAILY_LIMIT` (40, до 500) запитів на добу UTC на користувача — атомарно (`ai_claim_daily_quota`, ідея з гілки колеги), тайм-аут 30 с, 2 повтори для 429/5xx.
- Строк зберігання: діалоги без активності понад 90 днів і облік понад 180 днів видаляє щоденне завдання `orbix-ai-cleanup`. Користувач може видалити свій діалог.

## Перевірено
- `tests/ai.test.mjs` (16 тестів, входять у `npm test`): адаптер (виклики інструментів, повтори, квота, тайм-аут, відхилений ключ), перевірка запиту, ліміти, історія; інструменти — псевдоніми, сума на бота й драбина як у runner, стан без вигаданих даних, ризик через `risk.js` (BNB 7 490 > 3 000 → блок), бектести, довідка; **повний діалог: у запитах до моделі немає пошти, імені бота, ID акаунта, ботів, ордерів і ключа**; prompt injection; обмеження раундів; обрізання великих результатів.

- Інтерфейс (Playwright, 360 px і 1280 px): вхід не виконано, функцію не викладено, робочий діалог, історія, ліміт, помилка 429, контекст із картки бота; без горизонтального прокручування, без помилок JS, axe — 0 порушень; HTML у відповіді моделі не виконується.
